# Linux 目录结构与 FHS 标准

## 一、FHS 概述

Linux 操作系统采用树形目录结构，所有文件和目录从根目录 `/` 开始。FHS（Filesystem Hierarchy Standard）定义了 Linux 系统中每个目录的用途和包含内容的标准，确保各发行版之间的一致性。

### 1.1 路径

正是由于FHS标准，在 Linux 操作系统下要寻找或操作某一个文件时，例如要查看全局配置文件下的用户账户文件时，就需要通过路径访问该文件（即`/etc/passwd`）。路径又分为**绝对路径**和**相对路径**两种

- 绝对路径：以根目录为起始的完整路径，能够唯一标识文件或目录的位置，同一绝对路径指向的文件在系统中仅有一个，无论当前目录如何，绝对路径始终指向同一位置
- 相对路径：依赖上下文目录，以当前位置为参照的路径。相对路径的开头有多种写法，以绝对路径的`/etc/passwd`文件为例，假设当前目录是`/etc/`下，那么`passwd`、`./passwd`都可以用于表示`/etc/passwd`文件

为了区别超级用户与普通用户，超级用户的家目录使用一条单独的路径`/root/`，但无论是哪种类型的用户，家目录的相对路径都可以统一用`~`号表示。

## 二、目录结构详解

### 2.1 根目录 `/`

Linux 文件系统的起点，所有其他目录都挂载在其下。

### 2.2 常见目录用途

```notepad
/bin/    [存放普通用户可执行的基本命令（如 ls、cp），系统单用户模式仍需依赖此目录]
/sbin/   [存放系统管理命令，通常只有root用户可以执行（如 fdisk、ifconfig）]
/usr/    [Unix System Resources，常称呼为用户程序目录，存放应用程序和库文件]
  ├── /usr/bin/    [用户安装的应用程序]
  ├── /usr/lib/    [共享库文件,存放 /bin 和 /sbin 中命令所依赖的库文件]
  ├── /usr/share/  [架构无关的共享数据，用于存放手册页、图标等，是磁盘占用的大头之一]
  ├── /usr/src/    [内核源码存放目录，编译内核或安装驱动时常涉及此目录]
  └── /usr/local/  [编译安装软件的默认目录]
/etc/    [系统配置文件目录，所有配置文件集中存放]
/var/    [经常变化的文件，如日志、缓存、邮件等]
  ├── /var/log/    [系统和服务的日志文件]
  ├── /var/spool/  [队列数据目录，除了邮件，还包括打印队列、定时任务队列]
  ├── /var/lib/    [应用程序的可变数据，如数据库文件、包管理器的数据库等]
  └── /var/run/    [存放运行时的 PID 文件，重启后清空，是 /run 的软连接]
/home/    [普通用户的家目录]
/root/    [root用户的家目录]
/tmp/     [临时文件目录，所有用户可读写，重启通常清空文件]
/dev/     [设备文件接口，所有硬件设备在Linux中以文件形式访问]
/proc/    [虚拟文件系统，内核和进程信息映射到文件]
  └── /proc/[pid]/       [每个进程的详细信息目录]
/sys/     [系统内核对象虚拟文件系统，用于查看和动态修改内核/驱动参数]
  └── /sys/class/net/    [内核 sysfs 文件系统中专门存放网络设备类信息的目录]
/boot/    [存放内核引导文件，包含启动加载器文件（如GRUB配置）和内核文件（如vmlinuz）]
/mnt/     [临时挂载点]
/media/   [可移动介质挂载点（光盘、U盘）]
/opt/     [第三方软件可选安装目录]
/srv/     [服务数据目录（如Web服务数据）]
/run/     [进程运行时 PID 文件存放处]
```

`/sys`是 `sysfs` 文件系统的挂载点，将内核对象（如设备驱动）以文件形式展示，常用于**热调整内核参数**或修改设备属性

### 2.3 常见配置文件说明

```notepad
/var/
  ├── /var/spool/cron      [定时任务文件]
  ├── /var/log/messages    [系统主日志文件]
  └── /var/log/secure      [安全日志文件，包含SSH登录信息]
/dev/
  ├── /dev/null            [黑洞设备，丢弃写入的所有数据]
  ├── /dev/zero            [零字节源，读取产生无限空字符]
  └── /dev/random          [随机数设备]
/etc/
  ├── /etc/skel/*          [新用户家目录模板，复制到新用户 $HOME 下]
  ├── /etc/profile         [系统级环境变量和启动脚本（所有用户生效）]
  ├── /etc/bashrc          [系统级别名和函数]
  ├── /etc/motd            [用户登录后显示的公告信息]
  ├── /etc/issue           [登录前显示的信息（本地登录）]
  ├── /etc/issue.net       [登录前显示的信息（网络登录）]
  ├── /etc/hostname        [本地域名解析]
  ├── /etc/resolv.conf     [DNS客户端配置]
  ├── /etc/fstab           [文件系统挂载表（开机自动挂载）]
  ├── /etc/default/useradd [ useradd 命令的默认配置]
  ├── /etc/login.defs      [用户/组创建的默认配置]
  └── /etc/shells          [系统支持的Shell列表]
```

### 2.4 /proc 重要文件

```notepad
/proc/
  ├── /proc/cpuinfo    [ CPU 信息]
  ├── /proc/meminfo    [内存信息]
  ├── /proc/loadavg    [系统平均负载]
  ├── /proc/uptime     [系统运行时间（秒）]
  ├── /proc/mounts     [当前挂载情况]
  ├── /proc/diskstats  [磁盘状态]
  ├── /proc/net/dev    [网络接口流量]
  ├── /proc/interrupts [中断信息]
  ├── /proc/softirqs   [软中断信息]
  ├── /proc/cmdline    [内核启动参数]
  └── /proc/sys/       [可通过文件修改内核参数（sysctl）]
```

## 三、用户家目录与环境变量

### 4.1 命令提示符

命令提示符是Linux系统的核心控制台，操作指令在这里执行，默认情况下命令提示符简要的提供了3个信息：用户名、主机名、当前所在目录：

- 命令提示符以`#`号结尾表示当前用户登录身份为root
	```bash
	[root@localhost  ~]#
	[当前登录的用户@主机名 当前所在的目录]#
	```
- 命令提示符以$号结尾表示当前用户登录身份为普通用户
	```bash
	[test@node1  ~]$
	```

命令提示符`PS1`在`/etc/profile`文件最后一行添加配置即可永久生效，临时修改可以通过`export`直接修改变量

### 4.2 用户家目录初始化

`useradd`创建用户时会复制`/etc/skel`到家目录。若家目录损坏无法重建，可手动复制`/etc/skel`修复

```bash
cat /etc/default/useradd    # 查看useradd命令的默认配置文件
# useradd defaults file
GROUP=100
HOME=/home
INACTIVE=-1
EXPIRE=
SHELL=/bin/bash
SKEL=/etc/skel     # 创建新用户时会从/etc/skel目录下复制环境变量文件
CREATE_MAIL_SPOOL=yes

ls -A /etc/skel    # /etc/skel 目录下都是隐藏文件
.bash_logout  .bash_profile  .bashrc

cp -a /etc/skel/ /home/test/    # 复制并重命名/etc/skel/为用户的家目录
chown -R test:test /home/test/  # 家目录权限修正
```

用户家目录下有几个重要的环境变量文件

```notepad
~/
├── .bash_profile    [用户登录时执行（加载环境变量和脚本）]
├── .bashrc          [每次打开新Shell时执行（定义别名、函数）]
├── .bash_logout     [用户退出时执行]
└── .bash_history    [记录用户执行过的历史命令信息]
```

`~/.bash_history`文件不会实时保存历史命令信息，最新的历史命令信息保存在内存中，该文件会定时读取内存中的命令信息并写入，或者通过`history -w`命令手动写入

### 4.3 Shell类型

在Linux系统中，命令的执行依赖于解释器，Linux命令的执行会经过四个步骤：用户 -> 解释器 -> 内核 -> 硬件。Linux系统内核一般会具备多个解释器，支持的所有解释器都放在`/etc/shells`文件中，缺省情况下CentOS、RHEL发行版系列的操作系统会使用`/bin/bash`作为默认的解释器

```bash
echo $SHELL        # 查看当前用户的默认SHELL
/bin/bash

cat /etc/shells    # 查看系统支持的Shell列表
/bin/sh
/bin/bash
/usr/bin/sh
/usr/bin/bash
```

| Shell类型    | 说明                                               |
| :--------- | :----------------------------------------------- |
| 登录Shell    | SSH登录或本地登录，加载 `/etc/profile` → `~/.bash_profile` |
| 非登录交互Shell | 打开新终端，加载 `~/.bashrc` → `/etc/bashrc`             |
| 执行脚本       | 新建子Shell，只加载 `BASH_ENV` 指向的文件                    |

`/etc/profile`与`/etc/bashrc`两个文件比较容易混淆，`/etc/profile`中会调用`/etc/bashrc`，所以在使用两个文件时感知差异不会特别明显，在非图形化界面下差异会进一步弱化，只是理论上`/etc/bashrc`相对来说更容易触发（仅需新开窗口或调用bash）

与这两个全局配置文件对应的是用户环境变量文件`~/.bash_profile`和`~/.bashrc`，用户环境变量局部生效

### 4.4 PATH 环境变量

```bash
echo $PATH    # 查看当前PATH值
/root/.local/bin:/root/bin:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin

export PATH=$PATH:/opt/software   # 临时添加路径
echo "PATH=$PATH:/opt/software" >> /etc/profile.d/path.sh  # 永久生效
source /etc/profile               # 使文件即可生效
```

> **为什么有的命令执行后不需要`source`**

例如`hostnamectl`与`localectl`，`localectl`执行修改编码集后还需要手动`source`一下配置文件，是因为`localectl`命令没有包含`export`操作；`source`命令等同于`.`

## 四、Linux 文件类型

在 Linux 中，一切皆文件。文件类型标识（`ls -l` 首字符）：

| 标识  | 类型    | 说明              |
| :-- | :---- | :-------------- |
| `-` | 普通文件  | 文本、二进制、数据文件     |
| `d` | 目录文件  | 文件夹             |
| `l` | 符号链接  | 快捷方式            |
| `c` | 字符设备  | 逐字符访问的设备（键盘、终端） |
| `b` | 块设备   | 以块为单位访问（硬盘、光盘）  |
| `p` | 管道文件  | 进程间通信           |
| `s` | 套接字文件 | 网络/进程通信         |

```bash
# 示例：
# -rw-r--r--  1 root root  4096 Jan 1 12:00 file.txt
# lrwxrwxrwx  1 root root     7 Jan 1 12:00 link -> target
# crw-rw----  1 root root  4,  1 Jan 1 12:00 /dev/null
# brw-rw----  1 root root  8,  0 Jan 1 12:00 /dev/sda
```
