# NFS 网络文件系统

## 一、NFS 概述

NFS（Network File System）是一种分布式文件系统协议，让客户端能通过网络访问远程服务器的目录，就像访问本地一样。

### 1.1 NFS vs SAMBA

| 特性 | NFS | SAMBA |
| :--- | :--- | :--- |
| 协议 | NFS（SUN开发） | SMB/CIFS（Microsoft） |
| 跨平台 | 主要Linux/Unix | Windows/Linux/Unix |
| 场景 | Linux/Unix之间共享 | 异构平台共享 |
| 性能 | 高（原生Unix） | 较低 |
| 认证 | 依赖系统用户UID/GID | 支持独立用户密码 |

### 1.2 工作原理

NFS 基于 RPC（Remote Procedure Call）实现，依赖 `rpcbind` 服务进行端口注册：

1. 服务端启动，向 rpcbind 注册端口
2. 客户端请求，rpcbind 返回实际端口
3. 客户端直接与NFS服务通信
4. 数据通过内核的 VFS（Virtual File System）层处理

## 二、服务端部署

### 2.1 安装

```bash
yum install -y nfs-utils rpcbind

# 启动服务（必须先启动rpcbind）
systemctl start rpcbind
systemctl start nfs-server
systemctl enable rpcbind nfs-server
```

### 2.2 配置exports

```bash
vim /etc/exports
# 格式：共享目录    客户端(选项)
# 示例：
/data  192.168.1.0/24(rw,sync,all_squash,no_root_squash)

# 常用选项
rw          # 读写（默认ro）
ro          # 只读
sync        # 同步写入（数据写入磁盘后才响应客户端）
async       # 异步写入（性能更好，但可能丢数据）
all_squash  # 所有用户映射为nfsnobody
no_root_squash  # root用户保留root权限（慎用）
root_squash     # root用户映射为nfsnobody（默认）
anonuid=xxx     # 指定匿名用户UID
anongid=xxx     # 指定匿名用户GID
no_subtree_check    # 禁用子目录检查（性能优化）
no_wdelay        # 禁用写延迟

# 多个客户端示例
/data  192.168.1.0/24(rw,sync)  172.16.0.0/16(ro)
```

### 2.3 生效配置

```bash
# 重新读取exports配置
exportfs -r
# -a: 导出所有目录
# -r: 重新导出所有（读取/etc/exports）
# -u: 取消导出
# -v: 显示详情

# 查看导出状态
exportfs -v
showmount -e localhost
```

### 2.4 防火墙配置

```bash
firewall-cmd --add-service=nfs --permanent
firewall-cmd --add-service=rpc-bind --permanent
firewall-cmd --add-service=mountd --permanent
firewall-cmd --reload
```

## 三、客户端挂载

### 3.1 基本挂载

```bash
# 查看服务端共享目录
showmount -e 192.168.1.100

# 临时挂载
mount -t nfs 192.168.1.100:/data /mnt/nfs

# 开机自动挂载
vim /etc/fstab
192.168.1.100:/data  /mnt/nfs  nfs  defaults,_netdev  0  0

# 参数说明
# _netdev: 网络服务就绪后再挂载
# soft/hard: 客户端超时处理方式
# intr: 允许中断请求
# timeo=xxx: 超时时间（单位0.1秒）
# rsize=32768,wsize=32768: 读写缓冲区大小（优化性能）
```

### 3.2 自动挂载（autofs）

autofs 是一种按需挂载机制，访问时才自动挂载，空闲超时后自动卸载。

```bash
# 安装
yum install -y autofs

# 配置主文件
vim /etc/auto.master
/misc   /etc/auto.misc

# 创建子配置文件
vim /etc/auto.misc
nfs     -rw,sync,soft   192.168.1.100:/data

# 启动服务
systemctl enable --now autofs

# 访问时自动挂载
ls /misc/nfs
```

## 四、权限问题分析

### 4.1 常见问题：写入被拒绝

服务端 `all_squash` 会将所有客户端用户映射为 `nfsnobody`：

```bash
# 服务端检查
ls -ld /data
# drwxr-xr-x  5 root root  4096 Jan  1 12:00 /data

# nfsnobody UID 默认65534（CentOS 7）或65535（CentOS 6）

# 解决方法1：修改目录权限
chown nfsnobody:nfsnobody /data

# 解决方法2：指定匿名用户UID
vim /etc/exports
/data  192.168.1.0/24(rw,sync,all_squash,anonuid=1000,anongid=1000)
```

## 五、NFS 性能优化

```bash
# 客户端优化挂载选项
mount -t nfs -o rw,sync,no_wdelay,rsize=1048576,wsize=1048576,intr,hard,intr,timeo=50 192.168.1.100:/data /mnt/nfs

# 参数说明
rsize/wsize    # 读/写块大小（越大性能越好，受网络MTU限制）
sync           # 同步写入
no_wdelay     # 禁用写延迟
hard/intr     # 硬挂载+允许中断
timeo=50      # 超时50分秒
```

## 六、故障排查

```bash
# 1. 检查服务状态
systemctl status rpcbind
systemctl status nfs-server
rpcinfo -p localhost

# 2. 检查导出配置
exportfs -v
cat /var/lib/nfs/etab

# 3. 检查客户端挂载
mount | grep nfs
mount -vvv 192.168.1.100:/data /mnt/nfs  # 详细输出

# 4. 网络连通性
showmount -e 192.168.1.100
rpcinfo -p 192.168.1.100

# 5. 常见错误
# "mount: mount.nfs: access denied" → 检查exports配置和服务端目录权限
# "mount: mount.nfs: Connection refused" → 检查rpcbind和nfs-server是否启动
# "Stale file handle" → 服务端目录被卸载后重新挂载，客户端需要重新挂载
```
