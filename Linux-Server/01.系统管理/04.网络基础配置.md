# Linux网络

## 一、基础管理

### 1.1 主机名

1. 查看主机名

   ```bash
   hostname
   hostnamectl
   uname -n
   ```

2. 临时修改主机名

   ```bash
   hostname pc80.example.com    # 立刻生效
   ```

3. 永久修改主机名

   ```bash
   # 修改主机名配置文件
   echo "pc80.example.com" > /etc/hostname
   
   # 命令修改主机名
   hostnamectl set-hostname pc80.example.com
   ```

   修改主机名配置文件的方式需要系统重启生效，`hostnamectl`命令可以使主机名修改立刻生效，重启shell进程即可


### 1.2 网卡重命名

1. 修改引导文件

   `/etc/default/grub`是由内核读取的一个引导文件，通过这个引导文件可以制定内核识别网卡的规则，通过修改内核识别网卡的规则，将所有网卡统一命名为ethx类型。在深入学习理解Linix内核之前，这两个参数只需要记下即可

   ```bash
   vim /etc/default/grub
   GRUB_CMDLINE_LINUX="crashkernel=auto rd.lvm.lv=centos/root rd.lvm.lv=centos/swap rhgb quiet net.ifnames=0 biosdevname=0"    # 尾部补充两个参数
   ```

2. 动态生态GRUB2引导配置文件

   ```bash
   grub2-mkconfig -o /boot/grub2/grub.cfg
   ```

3. 修改网卡配置文件

   ```bash
   mv /etc/sysconfig/network-scripts/ifcfg-eno16777736 /etc/sysconfig/network-scripts/ifcfg-eth0
   sed -i 's/eno16777736/eth0/g' /etc/sysconfig/network-scripts/ifcfg-eth0
   ```
   
3. 重启系统

   ```bash
   reboot
   cat /proc/cmdline    # 确认内核参数修改成功，也可以直接看网卡名是否修改成功
   ```

> **grubby**
>
> RHEL 10系更新了GRUB配置的管理策略，`grub2-mkconfig`命令不再作为修改单个内核的参数的工具，它更多的被用于**全局性的、初始化级别的配置同步**，例如将`/etc/default/grub`文件中的默认设置应用到所有启动项中。在RHEL 10版本中，这个组合已经无法用于修改网卡名。
>
> 在RHEL 10版本，系统的启动项采用BLS（Boot Loader Specification）规范，每个内核的启动参数都独立存放在`/boot/loader/entries/`目录下的独立配置文件中，这一点从RHEL 10版本的`/etc/default/grub`配置文件中可以看到：
>
> ```bash
> cat /etc/default/grub
> ...
> GRUB_ENABLE_BLSCFG=true
> ```
>
> 在RHEL 10版本推荐使用新工具grubby修改内核参数，该工具的强大之处在于它能直接修改这些BLS配置文件（如对`/boot/grub2/grub.cfg`进行操作），从而改变内核的启动参数。在RHEL 10版本下修改网卡名步骤：
>
> ```bash
> grubby --update-kernel=ALL --args="net.ifnames=0 biosdevname=0"    # 修改内核参数
> reboot               # 重启系统以生效
> cat /proc/cmdline    # 系统重启后查看内核启动参数是否生效
> ```

### 1.3 配置IP

1. 临时修改IP

   ```bash
   # ip命令
   ip address show                           # 查看IP地址
   ip address add 80.80.80.80/24 dev eth0    # 为eth0网卡添加一个临时地址
   ```

2. 永久修改IP

   通过直接修改配置文件或nmcli命令都可以实现永久性修改IP信息，使用nmcli命令时需要确保NetworkManager服务处于启用状态。nmcli命令的优势在于会自动生成配置文件，在命令行使用nmcli命令时参数有误会直接报错，且不会生成错误的配置文件；nmcli命令会为每个网卡创建一个只有nmcli能够识别的“别名”，nmcli对网络的管理都是通过对“别名”的管理实现的，下文中统一将此“别名”称为“链接名”。

   ```bash
   # nmcli命令
   nmcli connection show            # 查看所有链接名与网卡的绑定关系
   nmcli connection delete ens33    # 删除链接名
   nmcli connection add type ethernet ifname eth0 con-name eth0 ipv4.method manual ipv4.addresses 192.168.31.80/24 ipv4.gateway 192.168.31.1 ipv4.dns 192.168.31.1 connection.autoconnect yes
   	type：设备类型
   	con-name：链接名
   	ifname：物理网卡名
   	ipv4.method：IP获取方式，manual代表手动设置
   	ipv4.addresses：IPv4地址
   	ipv4.gateway：网关地址
   	ipv4.dns：DNS服务器地址
   	connection.autoconnect：开机自动启用
   nmcli connection up eth0    # 使用链接名激活网络
   nmcli device status         # 查看设备
   nmcli connection modify eth0 ipv4.method auto    # 设置网卡配置为DHCP自动获取IP
   
   
   # 网卡配置文件
   vim /etc/sysconfig/network-scripts/ifcfg-eth0
   TYPE="Ethernet"	
   BOOTPROTO="static"    # 可选 none/static/dhcp
   DEFROUTE="yes"        # 开启默认路由
   NAME="ens33"          # 逻辑设备名
   UUID="84a691eb-145e-4e16-8220-e93751379fee"
   DEVICE="ens33"        # 物理设备名
   ONBOOT="yes"          # 开启自启用
   
   # 静态IP配置
   IPADDR="192.168.42.127"
   PREFIX=24             # 或者使用 NETMASK=255.255.255.0
   GATEWAY="192.168.42.2"
   DNS1="192.168.42.2"   # 网卡配置DNS服务器IP
   DNS2="114.114.114.114"
   
   # IPv6配置
   IPV6INIT=yes
   IPV6ADDR=2001:db8::100/64
   IPV6_DEFAULTGW=2001:db8::1
   ```
   
   CentOS 7版本修改网卡配置文件后需要重启网络服务`systemctl restart network`，使网卡配置修改生效；RHEL 10版本使用nmcli修改网卡配置，同样需要重新激活网卡。

> **网卡配置文件**
>
> 从RHEL 10版本开始，`/etc/sysconfig/network-scripts/`目录已被废弃，网卡配置文件存放在`/etc/NetworkManager/system-connections/`目录下

> **nmcli帮助手册**
>
> `man nmcli-examples`，nmcli相关参考：NetworkManager(8)，nmcli(1)，nmcli-examples(7)，nm-settings(5)，ip(8)，ip-address(8)
>
> 在NetworkManager的管理哲学中，device是一个网络接口，connection是device的配置，它们之间有如下关系：
>
> - 对任何一个device，同一时间只能有一个connection处于激活状态
> - 每个connection具有一个名称（ID）
> - /etc/sysconfig/network-scripts/ifcfg-name文件存放着connection的配置信息，其中name字段是connection的名称
>
> 在RHEL 10版本，connection的配置文件已经修改存放路径位置了，在/etc/NetworkManager/system-connections/目录下，并且在这些配置文件下默认取消了name字段，取而代之的是直接使用id字段

### 1.4 配置DNS

DNS解析分配本地解析和全局解析，本地解析通过`/etc/hosts`文件实现，优先级高于全局解析，全局解析通过`/etc/resolv.conf`文件实现，两者都是修改配置文件后立即生效。还有一种配置DNS解析的方式，直接在网卡配置文件中写入DNS服务器IP，网卡配置文件的DNS配置优先于`/etc/resolv.conf`文件。

```bash
# 本地DNS解析
vim /etc/hosts
127.0.0.1   localhost localhost.localdomain
::1         localhost localhost.localdomain
192.168.1.100   web01 web01.example.com

# 全局DNS解析
echo "nameserver 223.5.5.5" >> /etc/resolv.conf
cat /etc/resolv.conf
```

## 二、远程管理

### 2.1 免密登录

1. 创建密钥对

   ```bash
   ssh-keygen
   Generating public/private rsa key pair.
   Enter file in which to save the key (/root/.ssh/id_rsa):    # 密钥对保存路径，缺省保存在用户家目录下，不建议修改路径
   Created directory '/root/.ssh'.
   Enter passphrase (empty for no passphrase):    # 为密钥对设置密码，缺省为空密码
   Enter same passphrase again:                   # 确认密码，不设置密码
   ```

2. 向目标主机传递公钥

   ```bash
   ssh-copy-id root@192.168.0.81
   ```

3. 重要文件

   ```bash
   # 源主机
   cat ~/.ssh/known_hosts    # 此文件用于记录源主机已经远程管理过的机器
   
   # 目标远程主机
   cat ~/.ssh/authorized_keys    # 保存公钥的配置文件，此配置文件用于保存的其他源主机的公钥信息
   ```

   免密登录本质上是采用密钥对的方式进行远程管理，一旦公钥部署完成，即便目标远程主机上的用户密码发生变更，也不会影响到登录，只有当目标远程主机上的保存公钥的配置文件被删除，才会影响到免密登录

# 日志

日志用于记录操作系统、应用程序在运行过程中发生的各种事件，通过日志内容可以查看及排除运行故障，同时日志也是信息安全控制的重要依据，日志会记录用户的各种操作行为。CentOS 7系统的日志由rsyslog服务统一记录、管理，rsyslog服务定义了写入日志的文本格式、文件存放路径等

**常见的系统日志**

| 日志文件          | 主要用途                         |
| ----------------- | -------------------------------- |
| /var/log/messages | 记录内核信息、各种服务的公共信息 |
| /var/log/dmesg    | 记录系统启动过程的各种信息       |
| /var/log/cron     | 记录与cron计划任务相关的信息     |
| /var/log/maillog  | 记录邮件收发相关的信息           |
| /var/log/secure   | 记录与访问限制相关的安全信息     |

**用户日志**

用户日志也有专门的配置文件进行记录，但Linux认为用户日志数据比较敏感，用户日志的配置文件无法直接查看其内容，用户日志信息由登录程序负责采用二进制格式记录、管理，用于记录登录用户的时间、来源、执行的命令等信息，虽然无法直接观察用户日志信息的配置文件，但可以通过命令查看日志信息

| 日志文件         | 主要用途                         | 对应命令      |
| ---------------- | -------------------------------- | ------------- |
| /var/log/lastlog | 记录最近的用户登录事件           |               |
| /var/log/wtmp    | 记录成功的用户登录/注销事件      | last          |
| /var/log/btmp    | 记录失败的用户登录事件           | lastb         |
| /var/run/utmp    | 记录当前登录的每个用户的相关信息 | users、who、w |

users、who、w 命令都是用于查看已登录的用户信息，只是三个命令的详细度不同

```bash
who
root     tty1         2026-10-14 21:45                    # tty表示远程命令行终端
root     pts/0        2026-10-30 12:54 (192.168.0.249)    # pts表示图形化下的命令行终端；还有一种:0的字符，表示图形化

lastb -2    # 专门用于查看登录失败的用户记录
lisi     ssh:notty    192.168.0.249    Fri Oct 30 13:08 - 13:08  (00:00)
lisi     ssh:notty    192.168.0.249    Fri Oct 30 13:08 - 13:08  (00:00)

last -2     # 专门用于查看登录成功的用户记录
root     pts/0        192.168.0.249    Fri Oct 30 12:54   still logged in
root     pts/0        192.168.0.249    Fri Oct 30 12:45 - 12:54  (00:08)
root     pts/1        192.168.0.249    Fri Oct 30 09:49 - 12:32  (02:43)
```

### 1.1 使用journalctl工具

journalctl是CentOS 7版本推荐使用的日志搜集工具，提取由systemd-journal服务搜集的日志信息，主要包括内核/系统日志、服务日志，它比较适合用于查看服务的报错日志

```bash
journalctl
	-u：指定服务名称
	-n：显示消息条数
```

## 二、日志消息的优先级

Linux内核定义的事件紧急程度分为 0~7 共8种优先级别，数值越小表示其对应事件的紧急程度越高、越重要

| 数值 | 标记            | 说明                       |
| ---- | --------------- | -------------------------- |
| 0    | EMERG（紧急）   | 会导致主机系统不可用的情况 |
| 1    | ALERT（警告）   | 必须马上采取措施解决的问题 |
| 2    | CRIT（严重）    | 比较严重的情况             |
| 3    | ERR（错误）     | 运行出现错误               |
| 4    | WARNING（提醒） | 可能会影响系统功能的事件   |
| 5    | NOTICE（注意）  | 不会影响系统，但值得注意   |
| 6    | INFO（信息）    | 一般信息                   |
| 7    | DEBUG（调试）   | 程序或系统调试信息等       |
