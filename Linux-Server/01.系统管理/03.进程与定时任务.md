# Linux 进程管理与定时任务

## 一、进程管理

进程与程序区别在于，程序指的是静态的没有运行的代码，进程指的是动态执行的代码，前者存放在磁盘中，后者会占用CPU与内存资源，真正提供软件功能的是进程，程序在运行之后才能成为进程。进程又被分为父进程和子进程，所有的子进程一定是由其父进程拉起的，一个父进程下可以拉起N个子进程，父进程与子进程之间是一个巨大的树型结构，每个进程在系统上都有一个唯一编号PID。

### 1.1 查询进程

#### ps — 进程快照

```bash
ps aux                 # 显示当前终端所有进程（a）、当前用户所在终端下的进程（x）、以用户格式输出（u）
USER    PID         %CPU            %MEM          VSZ      RSS     TTY   STAT    START       TIME     COMMAND
用户    进程ID   占用CPU的百分比   占用内存的百分比   虚拟内存   固定内存   终端   状态   起始时间   CPU处理时间   程序指令

ps -elf                # 显示系统内所有进程（-e）、以长格式输出信息（-l）、包括最完整的进程信息（-f）
ps -ef | grep nginx           # 查找nginx进程
ps aux --sort=-%cpu           # 按CPU排序（降序）
ps aux --sort=-%mem           # 按内存排序（降序）
```

ps指令的两种组合参数各有特点，aux显示的进程信息非常详细、elf会显示父进程的信息，PPID为父进程的PID

**STAT 进程状态：**
| 状态 | 含义 |
| :--- | :--- |
| R | 运行中（Running） |
| S | 睡眠（可中断） |
| D | 不可中断的睡眠（通常等待I/O） |
| T | 暂停/追踪（Stopped） |
| Z | 僵尸进程（Zombie） |
| s | 会话首进程 |
| N | 低优先级 |
| l | 多线程 |

#### top — 动态进程监控

```bash
top                            # 启动top（默认3秒刷新）
    -d：指定刷新时间，以秒为单位
    -p：指定进程的PID，监控特定进程
    -u：指定用户名，监控特定用户的进程
top -b -n 2 > top.log         # 批量模式：执行2次输出到文件
    -b：批处理模式；关闭交互界面和键盘控制、输出纯文本
    -n：指定迭代次数；通常会迭代2次，首次采到的数据是历史平均值，参考意义有限，第二次是瞬时数据

# top 交互命令
# P：按CPU排序（默认）
# M：按内存排序
# N：按PID排序
# T：按时间排序
# k：终止进程
# r：修改nice值（优先级）
# q：退出
# 1：显示所有CPU核心
# f：自定义显示字段
```

top工具统计的用户数量并不是按照用户名来算的，是按照会话数量计算的。例如，root用户分别通过图形化、Xshell远程工具、命令行字符界面进行登陆，三个会话在top工具中会显示为3个用户正在登陆，即便在图形化窗口中再开启一个终端窗口，这也算一个登陆用户。

后台挂起进程的是节省系统资源的机制，业务压力不大时不需要过多的进程占用系统资源；僵尸进程指的是意外终止对外提供服务，但仍在占用系统资源的进程，因此僵尸进程也需要管理员手动终止。除了top命令能看到的这两种进程，还有一种异常进程被称为孤儿进程，孤儿进程指的是父进程在终止其子进程时遗漏的子进程，孤儿进程在失去父进程的约束后，会认为整个系统资源都是可用的，可能会大量占用CPU、内存资源。

CentOS 7系列的systemd进程会自动查找系统中的孤儿进程，并将其终止。

#### pstree — 进程树

```bash
pstree                         # 显示进程树
pstree -p                      # 显示PID
pstree -u                      # 显示用户
pstree -ap user01             # 显示user01的完整进程树
```

#### pgrep — 查找进程

```bash
pgrep nginx                    # 查找nginx的PID
pgrep -u root nginx            # 查找root用户运行的nginx
pgrep -f "python.*script"     # 匹配命令行
```

### 1.2 进程控制

#### 挂起与恢复

```bash
# Ctrl+Z：挂起当前进程到后台
# jobs：查看后台任务
# fg %n：将任务n调回前台
# bg %n：将任务n在后台恢复运行
```

#### nohup / & — 后台运行

```bash

nohup ./script.sh > output.log 2>&1 &

# &：后台运行（退出终端会终止）
# nohup：不挂断运行（忽略SIGHUP信号）
# screen/tmux：推荐替代方案
```

#### kill — 终止进程

```bash
kill PID                       # 正常终止进程
kill -9 PID                    # 强制杀死（SIGKILL）
kill -15 PID                   # 优雅终止（SIGTERM，默认）
kill -l                        # 列出所有信号

# 常用信号
# 1  SIGHUP   挂起，重新读取配置（如reload）
# 9  SIGKILL  强制终止
# 15 SIGTERM 优雅终止（默认）
# 18 SIGCONT 继续（与STOP相反）
# 19 SIGSTOP 暂停
# 20 SIGTSTP 暂停（Ctrl+Z）

# 批量终止
kill -9 $(pgrep nginx)        # 杀死所有nginx进程
pkill nginx                    # pkill直接按名字杀
killall nginx                  # 杀死所有nginx进程（按名字）
```

### 1.3 进程优先级

```bash
# nice值范围：-20（最高优先级）~ 19（最低优先级）
```

## 二、定时任务

定时任务通常被用于按照设定的时间为用户执行某些固定的系统任务，定时任务又被分为一次性定时任务和周期性定时任务，两者软件包和工具各不相同，定时任务的重点会放在周期性定时任务上

cronie是CentOS 7系统默认的定时任务工具，也是周期性定时任务工具，与其相关的还有客户端执行程序crontab、系统守护进程crond、日志文件`/var/log/cron`；at是CentOS 7系统下的一次性定时任务工具，需要单独安装at软件包并启动atd服务，与其相关的包括客户端执行程序at、系统守护进程atd、日志文件`/var/log/cron`，atd的日志与crond的日志保存在同一文件中

### 2.1 周期性定时任务crond

1. crontab命令

   ```bash
   crontab -e -u hebor
       -e：编辑定时任务
       -l：查看定时任务
       -r：删除用户的所有定时任务
       -u <user>：指定执行该定时任务的用户身份，不指定定时任务的用户时，默认为当前用户创建定时任务
       -i：执行命令前提示
       -x <mask>：启动调试模式
   ```

   配置crontab定时任务后，在`/var/spool/cron/`目录下会自动创建对应用户名文件

2. crontab基本语法格式

   使用crontab编辑定时任务时实际上就是通过文本编辑器编写执行的时间与执行的指令，crontab周期性定时任务的语法格式可以参照`/etc/crontab`文件

   ```bash
    分    时     日    月     周      任务命令行（绝对路径）
   0~59  0~23  1~31  1~12   0~7     0或7都代表星期日
   
   * * * * *          #每分钟执行一次
   5 * * * *          #每小时第5分钟执行
   30 8 * * *         #每天8点30执行一次
   * 8 * * *          #每天8点开始执行，每分钟执行一次，总共执行60次，直到9点不再执行
   30 23 * * 5        #每周五23点30执行一次
   30 23 * * 1-5      #每周的周一到周五的23点30执行一次
   30 23 * * 1,3,6    #每周的周一、周三、周六的23点30执行一次
   30 23 1 * 1        #每月的1号或每周一的23点30执行一次
   */5 * * * *        #每隔5分钟执行一次
   1 */2 * * *        #每隔2小时执行一次，如果将分钟改为*，则匹配一小时内的60分钟，实现的效果就是每个2小时执行60次
   */30 9-18 * * *    #每天9点到18点每30分钟执行
   ```

   crontab语法格式中对于执行时间的编写有4种方式：

   - *：匹配范围内的任意时间
   - ,：分割多个不连续的时间点
   - -：指定连续时间范围
   - /n：指定时间频率。例如，每n小时执行一次

   编写定时任务时建议使用crontab命令编辑，crontab可以自动检测配置文件的语法，也可以直接在`/var/spool/cron/`目录下创建对应用户名的配置文件，直接编辑配置文件实现定时任务。虽然两种方式最终实现的效果是一样的，但后者不仅没有语法检测，并且cron日志中也不会记录该配置文件的创建和编辑过程。

   每次创建定时任务后都需要检测定时任务是否生效，一般可以通过临时修改系统时间对定时任务进行测试，如果定时任务未生效，则需要查看定时任务日志进行检查。需要注意的是，计划任务会在内存中执行，它不会将执行结果直接输出到命令行，执行结果会输出到后台，会通过日志体现执行过程。例如，定时任务使用echo输出文本信息，不会直接在命令行输出信息。

3. 定时任务示例

   ```bash
   # 每分钟记录当前系统时间，写入/opt/time.txt
   crontab -e
   * * * * * /usr/bin/date >> /opt/time.txt
   crontab -l
   cat /opt/time.txt    # 检查文件内容
   crontab -r   
   ```

   使用`crontab -r`会清空当前用户的所有定时任务，如果需要单独删除某一条定时任务，仍使用`crontab -e`选项编辑即可，删除不需要的某一条定时任务。

### 2.2 系统定时任务

通过crontab编辑的定时任务都是针对用户的定时任务，即便不使用`crontab -u`指定用户，它默认为当前用户创建定时任务。cronie作为CentOS 7系统默认的定时任务工具，它在CentOS 7系统上具备4个固定执行时间的目录，将脚本文件直接放置在这些目录下即可周期性执行：

- 任务周期：每小时 `/etc/cron.hourly/`
- 任务周期：每天 `/etc/cron.daily/`
- 任务周期：每周 `/etc/cron.weekly/`
- 任务周期：每月 `/etc/cron.monthly/`

除了以上四个固定执行周期的定时任务目录，cronie还具备其独立的权限控制配置文件，用于管控是否允许普通用户具备设置其定时任务的权限：

- `/etc/cron.allow`：crontab白名单文件，默认不存在，用于允许指定用户可以使用crontab设置定时任务
- `/etc/cron.deny`：crontab黑名单文件，阻止指定用户不能使用crontab设置定时任务

需要注意的是，cronie的白名单文件权限优于黑名单文件，如果使用白名单文件可能会导致系统中大部分普通用户都失去配置定时任务的权限，系统默认未创建白名单文件。除了以上2个权限文件以外，还需要注意`/etc/crontab`文件，它是crontab定时任务的参考说明文件，不要在此文件下直接编辑定时任务。

日志文件切割处理`logrotate`任务是系统默认设置好的定时任务

```bash
vim /etc/logrotate.conf
# rotate log files weekly    # 每周切割保存一次日志
weekly


# keep 4 weeks worth of backlogs    # 仅保留最近4周的日志数据
rotate 4


# create new (empty) log files after rotating old ones    # 旧日志数据切割保存后创建新的空日志文件
create


# use date as a suffix of the rotated file    # 文件保存的命名以日期结尾
dateext


# uncomment this if you want your log files compressed    # 压缩日志数据文件
#compress
# delaycompress     # 总是与 compress 选项一起用，delaycompress 选项指示 logrotate 不要将最近的归档压缩，压缩将在下一次轮循周期进行。这在你或任何软件仍然需要读取最新归档时很有用。


# RPM packages drop log rotation information into this directory
include /etc/logrotate.d

/var/log/wtmp {    # 对指定日志数据文件自定义切割条件
    monthly    # 每月切割一次
    create 0664 root utmp    # 设置新建日志文件的权限、所属用户、所属组
        minsize 1M    # 切割日志文件最小1M大小
    rotate 1    # 只保留1个月的数据
}

/var/log/btmp {
    missingok   # 在日志轮循期间，任何错误将被忽略，例如 “文件无法找到” 之类的错误。
    monthly
    create 0600 root utmp
    rotate 1
}

# system-specific logs may be also be configured here.
```

### 2.3 定时任务编写技巧

定时任务配置文件中的符号信息

- *：每次    每分钟/每小时/每天/每月/每周
- */n：时间间隔    每隔n分钟/每隔n小时/每隔n天/每隔n月
- n-m：连续时间范围    n到m分钟/n到m小时...
- n,m：不连续的时间范围    n分钟和m分钟/n小时与m小时...

有时可能会看到 `m/n * * * *` 这样的写法，这表示到m分钟的前n分钟执行操作，例如 `30/10 * * * *` 表示`1:30`的前10分钟执行操作，小时位是循环的，可以是`2:30`、`3:30`等

编写定时任务时，上一级时间有设置时，尽量对下级时间也要设置，例如每天中午12点应该写成 `00 12 * * *` ，即便没有对分钟有具体声明，也应该对其有具体设置，如果分钟位不进行设置，也就是`*`分，这代表每天中午12点的每分钟都会执行一次动作，直到13点结束执行，中间会执行60次操作

定时任务的注意事项

1. 在定时任务中不能识别一些特殊的符号信息。例如`` ` ``号、`.`号等 -- 使用脚本执行定时任务
2. 无论是文件名或是命令，编写定时任务时要使用绝对路径 -- 定时任务能识别的环境变量`$PATH=/usr/bin:/bin`
3. 每个定时任务都需要注释说明
4. 当操作的命令超过2个时，尽量使用脚本文件
5. 每个定时任务的结尾使用错误重定向将错误输出内容重定向到/dev/null，避免磁盘空间被占用
6. 在定时任务中，执行命令尽量不要产生输出信息 -- 正常的警告或提示信息输出仍会产生邮件提示，例如使用tar命令时，省略-v选项，尽量使用相对路径压缩


错误示范

```shell
# 特殊符号不识别
00 12 * * * cp /etc/hosts >> /tmp/backup/hosts_$(date +%F).txt

# 脚本文件未使用绝对路径
00 12 * * * bash ./test.sh

# 定时任务环境变量不同导致命令执行有问题
00 12 * * * ip address show eth0 > /tmp/backup/hosts_

00 12 * * * echo $PATH > /tmp/backup/hosts
```

执行定时任务时可能会收到邮件`You have mail in /var/spool/mail/root`，这个邮件是由postfix服务产生的，**定时任务执行出错时**就会产生错误邮件

如果不想显示收到邮件的提示可以选择关闭postfix服务，但关闭postfix服务后仍然会产生邮件，这时产生的邮件会暂时保存到`/var/spool/postfix/maildrop/`目录中，此目录下可能会产生大量小文件，占用过多的inode。重启postfix服务时会将`/var/spool/postfix/maildrop/`目录的文件处理掉

### 2.4 一次性定时任务at

1. at命令

   ```bash
   # 非交互式编写定时任务
   echo "hello world" | at 14:55
   
   # 进入交互模式
   at 23:00
   at> /usr/bin/echo "hello world"
   at> <EOT>                        # Ctrl+D结束
   job 1 at Mon Dec 31 23:00:00 2025
   
   at -l                            # 查看任务列表
       -l：查看任务列表，atq命令可以实现同样的效果
       -c 1：查看ID为2的任务详情
       -d 1：删除ID为2的任务，atrm可以实现同样的效果
   ```

2. at常见语法格式

   ```bash
   at 23:00                          # 今天23:00执行
   at 23:00 2025-12-31               # 指定日期执行
   at now +5 minutes                 # 5分钟后执行
   at now +1 hour                    # 1小时后执行
   at 23:00 + 2 days                # 2天后的23:00
   ```

3. at权限管理

   与cronie一样，at也具备独立的权限控制配置文件，用于管控是否允许普通用户具备设置其定时任务的权限：

   - `/etc/at.allow`：at白名单文件，默认不存在，用于允许指定用户可以使用at设置定时任务
   - `/etc/at.deny`：at黑名单文件，用于阻止指定用户不能使用at设置定时任务

   白名单文件优先级高于黑名单文件，两个文件都不存在的情况下，只有root用户能够创建定时任务。

### 2.5 编写定时任务规范

```bash
# 1. 先测试命令是否能正常执行
# 2. 编写任务时使用绝对路径
# 3. 添加注释说明
# 4. 避免不必要的输出（重定向到/dev/null）
# 5. 复杂操作写入脚本

# 示例
crontab -e
# crond-01: sync time info    # 编写注释
*/10 * * * * /usr/sbin/ntpdate ntp1.aliyun.com &> /dev/null        # 不输出任何信息
```

## 三、日志管理

### 3.1 rsyslog

rsyslog 是 CentOS/RHEL 的日志服务，核心配置文件：`/etc/rsyslog.conf`

#### 配置文件格式

```
设施.级别    动作
例：
mail.info    /var/log/maillog
authpriv.*   /var/log/secure
*.info       @@192.168.1.100:514    # TCP发送到远程
```

**常用设施（Facility）：**
| 设施 | 说明 |
| :--- | :--- |
| auth/authpriv | 认证相关（login, su, ssh） |
| cron | 定时任务 |
| daemon | 守护进程 |
| kern | 内核 |
| mail | 邮件 |
| user | 用户程序 |
| local0-local7 | 本地程序自定义 |
| `*` | 所有设施 |

**日志级别（Level）：**
| 级别 | 说明 |
| :--- | :--- |
| emerg | 系统不可用 |
| alert | 必须立即处理 |
| crit | 严重 |
| err | 错误 |
| warn | 警告 |
| notice | 注意 |
| info | 信息 |
| debug | 调试 |
| `*` / none | 所有/无 |

### 3.2 常见日志文件

| 文件 | 说明 |
| :--- | :--- |
| `/var/log/messages` | 系统主日志（大多数服务日志） |
| `/var/log/secure` | 认证/安全日志（SSH登录、sudo） |
| `/var/log/maillog` | 邮件日志 |
| `/var/log/cron` | 定时任务日志 |

### 3.3 journalctl — systemd 日志

```bash
journalctl                        # 查看所有日志
journalctl -n 50                  # 查看最近50行
journalctl -f                     # 实时跟踪（tail -f）
journalctl --since "1 hour ago"  # 查看1小时内日志
journalctl --since "2025-01-01" --until "2025-01-02"
journalctl -u nginx.service       # 查看指定服务日志
journalctl -u nginx.service -n 20
journalctl -p err                 # 仅错误级别以上
journalctl --disk-usage           # 查看日志磁盘占用
journalctl --vacuum-size=500M     # 限制日志大小
```

### 3.4 logrotate — 日志轮转

主配置文件：`/etc/logrotate.conf`
用户配置目录：`/etc/logrotate.d/`

```bash
vim /etc/logrotate.d/nginx
/var/log/nginx/*.log {
    daily                    # 每天轮转
    missingok               # 丢失不报错
    rotate 14               # 保留14个文件
    compress               # 压缩旧日志
    delaycompress           # 延迟压缩（保留最近一个不压缩）
    notifempty             # 空文件不轮转
    create 0640 www-data www-data   # 轮转后创建新文件
    sharedscripts           # 所有日志轮转后只执行一次脚本
    postrotate
        [ -f /var/run/nginx.pid ] && kill -USR1 `cat /var/run/nginx.pid`
    endscript
}

# 手动执行（测试）
logrotate -f /etc/logrotate.conf
logrotate -d /etc/logrotate.d/nginx   # 模拟执行（不实际轮转）
```
