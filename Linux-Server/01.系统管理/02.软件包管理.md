# Linux 软件包管理

## 一、RPM 包管理

### 1.1 RPM 概述

RPM（RedHat Package Manager）由 Red Hat 开发，用于管理 Linux 软件包。RPM 包名格式：

```
软件名-版本信息.操作系统.硬件架构.rpm
例如：nginx-1.20.1-1.el7.x86_64.rpm
```

Linux系统会建立一个集中的数据库，用于记录软件包安装/卸载等变化信息，并分析软件包依赖关系；在windows系统中是依赖注册表来实现这个功能的。

RPM包的安装路径一般是不允许调整的，安装路径在程序中已经写死了，常见的RPM包的常规安装路径：

| 文件类别             | 默认安装位置                     |
| -------------------- | -------------------------------- |
| 普通执行程序         | /usr/bin/、/bin/                 |
| 服务器程序、管理工具 | /usr/sbin/、/sbin/               |
| 配置文件             | /etc/、/etc/软件名/              |
| 日志文件             | /var/log/、/var/log/软件名/      |
| 程序文档、man手册页  | /usr/share/doc/、/usr/share/man/ |

### 1.2 RPM 安装与查询

```bash
# 安装
rpm -ivh package.rpm
	-i：执行安装
	-v：显示详情
	-h：显示进度条
	--nodeps：忽略依赖安装（不推荐）
	--force：强制安装

# 查询；查询软件包信息主要依靠-q选项
rpm -qa | grep nginx       # 查找nginx包
rpm -qa                    # 列出所有已安装的包
	-ql：列出包的所有文件
	-qi：查看包信息
	-qc：查看包配置文件
	-qd：查看包文档文件
rpm -qf /usr/sbin/nginx    # 查询文件属于哪个包；基于RPM包管理原理，部分场景下即便删除该文件，仍可以使用rpm -qf查询“该文件”属于哪个包
rpm -q --scripts nginx     # 查看包安装/卸载脚本
rpm -qpl /mnt/cdrom/AppStream/Packages/v/vsftpd-3.0.5-10.el10.x86_64.rpm    # 查询未安装的包文件（-qp=query package）
```

使用`rpm -q nginx`同样可以查询当前linux系统中是否有安装名为“nginx”的包，这种方式与grep过滤的区别在于，`rpm -q`是严格匹配，任意一个字符的变化都会导致`rpm -q`查询不到软件包。除此以外，linux系统本身还有一个特性：在linux系统中安装的包名，与软件包安装后使用的命令，可能是不相同的。比如说，`rpm -q vim`查不到名为vim的包，但vim命令仍可以正常使用。

`rpm -qpl`命令的解析说明可能略有歧义，使用`-p`参数时必须指定某个软件包名，其作用是查看如果要安装这个软件包，会在linux系统上产生哪些文件。如果说`rpm -ql`是先安装软件包、再查询该软件包安装过程中产生了哪些文件；那么`rpm -qpl`就是在安装软件包之前、就先查看安装该软件包会产生哪些文件。

### 1.3 RPM 升级与卸载

```bash
# 升级
rpm -Uvh package.rpm              # 升级（没装过则安装）
rpm -Fvh package.rpm              # 强制升级（没装过则不安装）

# 卸载
rpm -e nginx                      # 卸载（包名，不是文件名）
rpm -e --nodeps nginx            # 忽略依赖卸载
rpm -e --allmatches nginx        # 卸载所有匹配版本
```

### 1.4 RPM 签名验证

在CentOS 7版本下，使用本地挂载镜像的方式安装、查看软件包时会收到操作系统发出的警告，声明没有找到软件包的签名信息。这个警告可能有2种情况：一是软件包内确实没有签名信息、二是操作系统不识别软件包的签名信息。本地挂载的镜像一般情况下都是带有签名信息的，只是系统默认不识别，此时导入下光盘中的签名文件即可。

Rocky 10版本似乎没有出现这个问题，即便不手动导入证书，也没有产生告警信息。

```bash
# 导入签名
rpm --import /mnt/cdrom/RPM-GPG-KEY-Rocky-10

# 验证签名
rpm --checksig /mnt/cdrom/AppStream/Packages/v/vsftpd-3.0.5-10.el10.x86_64.rpm
# 输出：package.rpm: rsa sha1 (MD5) pgp md5 OK

# 验证文件完整性
rpm -Va                            # 验证所有已安装的文件
# 输出格式：S.M.C.G.U.D（文件大小/权限/类型/所有者/组/修改时间）
```

## 二、YUM/DNF 包管理

### 2.1 YUM 概述

RPM包的一个特性是，当A程序的运行需要python环境时，A软件包会将python环境打包到RPM包中，如果B程序也需要python环境，B软件包可能会直接做一个判断，“系统中是否已安装A包”，如果没有就需要先安装A包，这就是依赖关系。linux系统发展至今，各个软件包之间的依赖关系早就错综复杂，属于是RPM包的历史遗留问题（开发者太懒了）。

YUM（Yellowdog Updater Modified）是基于 RPM 的包管理器，主要用于解决安装RPM包的依赖关系问题，使用`yum`安装一个软件包时，`yum`会自动分析并下载安装其所需的所有其他软件包（依赖），免去了手动寻找和安装的繁琐过程。

YUM使用最常见的C/S结构，YUM软件包仓库实际上就是指的Server端，Server端由两部分组成：软件包、仓库数据文件；软件包不必多说，仓库数据文件用于记录众多软件包的状态信息，类似于菜单的作用。

### 2.2 本地YUM仓库搭建

常规情况下，各个linux发行版的iso镜像文件中已经打包好了软件包和仓库数据文件，因此YUM Server端的配置在挂载iso镜像的那一刻就已经完成了，以Rocky Linux为例，其软件包和仓库数据文件分别存放在`AppStream/Packages`、`AppStream/repodata`两个目录下，所以本地YUM仓库的搭建主要是YUM Client相关的配置。

YUM Client的配置同样有几个注意事项，所有的Client配置文件都必须集中存放在`/etc/yum.repos.d/`目录下；允许存在多个Client配置文件，但所有配置文件需要以`.repo`为后缀；任意一个`.repo`的Client配置文件有误，都会影响到所有的Client配置，导致YUM不可用。

```bash
mkdir /mnt/cdrom                   # 创建挂载点
mount /dev/sr0 /mnt/cdrom          # 挂载镜像
vim /etc/yum.repos.d/local.repo    # 新建本地YUM Client配置文件
[local]                                   # yum源名称，具有唯一性
name = Local Repository                   # yum仓库的描述信息
baseurl = file:///mnt/cdrom/AppStream/    # 指定yum server的位置
enabled = 1                               # 是否启用此yum源配置
gpgcheck = 0                              # 关闭签名验证
#gpgkey = /mnt/cdrom/RPM-GPG-KEY-Rocky-10 # 启用签名验证时，需要指定签名文件位置

yum repolist                       # 列出系统当前可用的yum仓库，一般也用于配置完YUM Client配置文件后进行验证
```

### 2.3 基础命令

```bash
# 查询
yum list                          # 列出所有包
yum list installed                # 列出已安装的包
yum list httpd                    # 查看特定包，也可以用于搜索包
yum search httpd                  # 搜索包，search与list的区别就在于，list是严格匹配、search是模糊匹配
yum provides /usr/sbin/nginx      # 查找命令属于哪个包
yum info nginx                    # 查看包信息

# 安装/升级/卸载
yum install -y nginx              # 自动确认安装
yum localinstall package.rpm      # 本地安装（自动处理依赖）
yum update nginx                  # 升级
yum update                        # 升级所有包
yum remove nginx                  # 卸载（自动卸载依赖）
yum erase nginx                   # 卸载（更彻底）

# 缓存管理
yum makecache                     # 生成缓存
yum clean all                     # 清除所有缓存
yum clean metadata                # 清除元数据缓存
```

执行`yum remove`时不建议带上`-y`选项，`yum remove`在卸载软件时会自动判断卸载目标软件包后，有哪些其他包无法独立运行，无法独立运行的包都会作为目标软件包的依赖包一同卸载。例如，`yum remove httpd`在卸载httpd包时，yum判断mod_http2包在卸载httpd包之后无法独立运行，那么mod_http2这个包也会被一并卸载，如果此时又有其他软件包依赖mod_http2运行，那么相应的包也会一并被卸载。

所以`yum remove`的影响范围不可控，在执行卸载命令时不带上`-y`选项是留有一定的余地，避免重要的软件被一并卸载。

yum本身的缓存管理功能是为了提高运行效率，首次执行`yum repolist`时，yum会自动将yum仓库的元数据保存到本地磁盘，并在内存中生成缓存数据，下次再执行`yum repolist`时就会从内存中直接读取缓存数据。也由于这个机制，一旦管理员手动修改了yum配置文件，`yum repolist`仍会从内存中读取数据，这导致最新的yum配置文件无法生效，这种场景下就需要清理缓存。

还有一个冲突的点，既然有了`yum repolist`命令，为什么还需要`yum makecache`命令生成缓存呢？`yum repolist`的本职工作是查看yum仓库的状态，下载元数据、生成缓存都只是顺带做的事；`yum makecache`的主要功能就是下载元数据，`yum makecache`或`yum makecache --force`可以越过缓存机制强制从yum仓库下载最新的元数据。在RHEL 10版本，`yum makecache` 被设计为一个独立的系统定时器（`dnf-makecache.timer`）。系统会每天定时在后台自动执行 `dnf makecache`，确保缓存始终是最新的，`yum repolist`几乎已经不在承担下载功能。

### 2.4 YUM 组管理

```bash
yum grouplist                     # 列出软件组
yum groupinstall "Development Tools"   # 安装开发工具
yum groupinfo "Development Tools"     # 查看组信息
yum groupremove "Development Tools"   # 卸载组
```

### 2.5 YUM 历史

```bash
yum history                       # 查看操作历史
yum history info 5                # 查看第5号操作的详情
yum history undo 5                # 撤销第5号操作
yum history redo 5               # 重做第5号操作
```

### 2.6 自建 YUM 仓库

一般情况下，涉及到自建YUM仓库，则意味着仓库中的软件包是自定义的，此时不仅需要手动准备软件包，还需要根据实际的软件包信息构建仓库数据文件。













YUM的搭建一般分为两种模式：本地YUM仓库和远端YUM仓库，本地YUM仓库将Server端和Client端集中存放在本机机器上，因此无需网络连接；远端YUM仓库则需要通过FTP协议或HTTP协议将软件包从Server端下载到本地进行安装，在使用YUM安装软件包时，默认情况下会跟用户再次确认是否安装软件，此时用户可以选择确认安装、拒绝安装或仅下载软件包到本地但不安装

建立YUM源服务，常见的方式有2种：一种是将本地iso镜像挂载到系统，直接下发iso镜像中的软件包，由于ISO镜像中仓库数据文件是自带的，存放在`/repodata/`路径下，因此本地iso镜像的方式建立YUM源服务比较简单；另一种是将外网YUM源的包同步到本地后再下发。`reposync`工具就用于将外网yum源的包同步到本地，`reposync`工具被包含在`yum-utils`包中，所以要使用`reposync`命令时需要安装`yum-utils`包；通过`reposync`同步外网软件包后，还需要通过`createrepo`命令生成本地的软件仓库源，即为存放于本地的众多RPM软件包提供索引，自动化分析各软件包之间所需依赖关系，并生成元数据

通过`yum repolist`命令可以查看系统中配置了哪些网络yum，并查看其对应的`repo id`，`reposync`命令也可以通过`--repoid=[repo id]`选项，只同步指定的源到指定目录

## 三、本地 YUM 仓库搭建

### 3.1 创建本地 YUM 源

当服务器无法联网时，可使用本地 ISO 镜像作为 YUM 源：

```bash
# 1. 挂载系统镜像
mount /dev/cdrom /mnt

# 2. 创建本地源配置文件
vim /etc/yum.repos.d/local.repo
[local]
name=Local Repository
baseurl=file:///mnt
enabled=1
gpgcheck=0          # 关闭签名验证

# 3. 验证
yum list
```

epel源中存放的软件是*测试不够全面但是无害，所以无法放入base源中的软件*

### 3.2 使用 ISO 镜像文件

```bash
# 1. 将ISO镜像复制到系统
cp /path/to/CentOS-7-x86_64-DVD-2009.iso /opt/

# 2. 挂载ISO文件
mount -o loop /opt/CentOS-7-x86_64-DVD-2009.iso /mnt

# 3. 配置同上
```

### 3.3 搭建局域网 YUM 源

```bash
# 服务端（安装createrepo工具）
yum install -y createrepo httpd
createrepo /var/www/html/localrepo/

# 将RPM包放入/var/www/html/localrepo/
# 启动httpd
systemctl enable --now httpd

# 客户端配置
vim /etc/yum.repos.d/lan.repo
[lan]
name=LAN Repository
baseurl=http://server_ip/localrepo/
enabled=1
gpgcheck=0
```

## 四、系统服务管理

### 4.1 systemctl 基础命令

```bash
# 启动/停止/重启
systemctl start nginx
systemctl stop nginx
systemctl restart nginx           # 重启
systemctl reload nginx           # 重载配置（不中断服务）

# 查看状态
systemctl status nginx
systemctl is-active nginx        # 查看是否运行
systemctl is-enabled nginx       # 查看是否开机启动

# 开机启动
systemctl enable nginx           # 开机启动
systemctl disable nginx          # 禁用开机启动
systemctl enable --now nginx    # 启动+开机启动
systemctl disable --now nginx   # 停止+禁用开机启动

# 查看
systemctl list-units --type=service --all   # 列出所有服务
systemctl list-dependencies nginx           # 查看服务依赖
systemctl cat nginx                          # 查看服务配置文件
```

### 4.2 运行级别（target）

| SystemV runlevel | systemd target | 说明 |
| :--- | :--- | :--- |
| 0 | runlevel0.target, poweroff.target | 关机 |
| 1 | runlevel1.target, rescue.target | 单用户救援模式 |
| 2 | runlevel2.target, multi-user.target | 多用户（无NFS） |
| 3 | runlevel3.target, multi-user.target | 多用户（命令行） |
| 4 | runlevel4.target, multi-user.target | 多用户（保留） |
| 5 | runlevel5.target, graphical.target | 图形界面 |
| 6 | runlevel6.target, reboot.target | 重启 |

```bash
# 切换运行级别
systemctl isolate multi-user.target    # 切换到命令行
systemctl isolate graphical.target      # 切换到图形界面

# 设置默认级别
systemctl set-default multi-user.target   # 命令行
systemctl set-default graphical.target     # 图形界面

# 查看默认级别
systemctl get-default

# CentOS 7的运行级别文件
ls /usr/lib/systemd/system/runlevel*.target -l

lrwxrwxrwx 1 root root 17 Jan  8  2021 /usr/lib/systemd/system/runlevel2.target -> multi-user.target
lrwxrwxrwx 1 root root 17 Jan  8  2021 /usr/lib/systemd/system/runlevel3.target -> multi-user.target

lrwxrwxrwx 1 root root 13 Jan  8  2021 /usr/lib/systemd/system/runlevel6.target -> reboot.target
```

### 4.3 服务配置文件

systemd 服务配置文件位于：

| 目录 | 说明 |
| :--- | :--- |
| `/usr/lib/systemd/system/` | 软件包提供的服务文件 |
| `/run/systemd/system/` | 运行时创建的服务（不持久） |
| `/etc/systemd/system/` | 系统管理员创建的服务（优先） |

```bash
# 示例：创建自定义服务
vim /etc/systemd/system/myservice.service
[Unit]
Description=My Service
After=network.target

[Service]
Type=simple
ExecStart=/usr/local/bin/myservice
Restart=on-failure
User=root

[Install]
WantedBy=multi-user.target

# 重载systemd配置
systemctl daemon-reload
systemctl enable --now myservice
```
