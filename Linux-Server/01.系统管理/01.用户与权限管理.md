# Linux用户与权限管理

## 一、用户管理

### 1.1 用户

Linux安全系统的核心是用户账户，系统中各种资源对象的访问权限也取决于登录系统时所使用的的账户，创建账户时会为每个账户分配一个唯一的UID，Linux系统会根据UID来跟踪对应的账户权限；Linux系统会为各种服务创建不同的账户，这些账户叫做*系统账户*，它们并不是真正的用户，是系统上运行的各种服务进程访问系统资源需要用到的特殊账户

- 超级管理员账户

  账户名称是root，uid永远是0

- 系统账户

  用于管理进程信息，一般不允许系统账户直接登录系统；Centos6中系统账户uid范围是1\~499，Centos7的系统账户uid范围是1\~999

- 普通用户

  相比较root用户，普通用户在系统权限上受到限制。根据`/etc/login.defs`配置文件中的`UID_MIN、UID_MAX`默认参数，普通用户的UID从1000开始编号，默认最大为60000，但UID的取值范围并不是只到60000

著名的傀儡用户nobody，部分没有专门的虚拟用户管理的某些服务，又不想用root用户进行管理时，就会用到nobody账户。在CentOS 7上nobody是uid为99的特殊用户，Ubuntu系统将nobody用户的uid设置为65534，RHEL的新版本系统中也将nobody账户的uid设置为65534

UID的范围在`/etc/login.defs`配置文件中定义，不同的Linux版本对普通用户的UID定义范围可能有差异，实际的UID范围可以通过此配置文件确认。它被 `useradd`、`usermod`、`su`、`passwd` 等工具读取，但**实际认证和密码强度检查通常由PAM模块控制**，所以这个文件更多是提供“默认值”和“传统策略”

### 1.2 用户组

用户组的作用是为了方便管理用户，Linux系统上许多权限限制可以针对用户组来设置，属于该用户组下的所有用户会享有用户组的权限，与用户账户UID类似，用户组也具备一个唯一标识GID，GID编号默认情况下也是从0开始编号，最大60000

Linux系统下每一个用户必须至少属于一个组，组名可以与用户名完全相同，一个用户也可以属于多个组。基于这种情况下，用户组由分为两类：基本组和附加组（从属组），在Linux系统上创建普通用户时，会同步创建与用户同名的用户组，并将用户与用户组绑定，这就是基本组；附加组由管理员单独创建，且由管理员将用户与附加组进行绑定

### 1.3 配置文件

| 文件              | 说明                                                         |
| :---------------- | :----------------------------------------------------------- |
| `/etc/passwd`     | 用户账户信息                                                 |
| `/etc/shadow`     | 用户密码（加密）                                             |
| `/etc/group`      | 用户组信息                                                   |
| `/etc/gshadow`    | 用户组密码                                                   |
| `/etc/login.defs` | 主要用于定义**用户账户、组账户、密码策略以及登录相关的一些默认行为** |

```bash
cat /etc/passwd
root:x:0:0:root:/root:/bin/bash
# 用户名:密码占位符:UID:基本组GID:账户描述:用户家目录:用户Shell程序的路径

cat /etc/shadow
hebor:$6$3zsTNd1e$h0XujmiKglxMy2fa72s4mcNoL.Bsgh63PaLnzcBOIm1BtVxqU4NihlgbxADADbdEZbRHmK8zb68P/2Mgc1MmR0:20252:0:99999:7:::
# 用户名:加密密码:自1970-1-1到上一次修改密码的间隔时间（天数）:密码最短修改间隔（至少需要使用N天以后才能修改）:密码最长修改时限:密码过期提醒时间（提前7天提醒密码即将过期）:密码过期宽限时间:账号失效时间:保留

cat /etc/group
hebor:x:1000:
# 组名:密码占位符:GID:本组的成员用户列表

cat /etc/gshadow
test01:!:hebor:root,hebor
# 组名::加密密码（!号表示组未设置密码）:组管理员:本组的成员用户列表
```

在早期的Linux上，/etc/passwd文件中有加密后的用户密码，但鉴于很多程序都需要访问/etc/passwd文件获取用户信息，这成为了一个安全隐患，现在绝大多数Linux系统都将用户密码单独存放在/etc/shadow文件中，只有特定程序才能访问这个文件，而/etc/passwd文件中的密码栏则改为了密码占位符`x`

### 1.4 用户家目录

`/etc/skel`目录特征

1. 此目录下的文件都是隐藏文件
2. 此目录能够协助修复被破坏的家目录

`/etc/skel`目录文件解析

- `.bash_profile`：用于定义环境变量，每次登录系统时执行
- `.bashrc`：此文件被用于永久保存用户独有的别名信息，这个文件最主要的特征是**每新建一个Bash环境时都会执行一次此文件的内容**（开启新的终端或新的SSH连接）
- `.bash_logout`：执行退出指令时，同时执行此文件内的命令信息。`logout`命令也可用于退出

除了`/etc/skel`目录下的三个文件以外，还有一个文件比较重要，存放在用户家目录下的`.bash_history`文件，此文件用于记录用户执行过的历史命令信息，但该文件并不会实时保存历史命令信息，最新的历史命令信息保存在内存中，`.bash_history`文件会定时读取内存中的命令信息并写入。`history -w`命令手动写入

`/etc/skel/`目录下保存了用户的初始环境变量文件。例如使用`useradd hebor`命令时，大致分为3个步骤

1. 创建用户并将用户信息写入/etc/passwd文件
2. 创建用户家目录，并通过`cp /etc/skel/* /home/hebor/`将sekl目录下的所有文件拷贝到新用户的家目录下
3. 修改用户家目录的数据权限信息，即`chown -r hebor.hebor /home/hebor/`

对以上步骤可以做个验证，在`/etc/skel/`目录下随意创建一个文本文件，然后新建一个用户，此刻新建的用户家目录下就存在新建的文本文件

```shell
# 1. 使用普通用户删除家目录下的所有数据
rm -rf ~/*

# 2. 重新登录该普通用户就会发现用户提示符出现异常，此时再用root用户删除普通用户的家目录，并复制/etc/skel/目录重命名为普通用户的家目录，直接cp /etc/skel/*目录下的文件可能会不生效
\rm -r /home/hebor/
echo 123 > /etc/skel/hebor.txt    # 新建测试文本文件
cp -a /etc/skel/ /home/hebor/
chown -R hebor.hebor /home/hebor/    # 修改用户家目录权限
# 3. 验证普通用户的提示符是否已正常，检查用户家目录下是否存在新建文件
```

## 二、用户管理命令

### 2.1 useradd — 创建用户

```bash
useradd user01                    # 创建普通用户
useradd -u 1500 user02            # 指定UID
useradd -d /home/custom user03    # 指定家目录，默认在家目录路径是/home/[用户名]
useradd -G wheel,sudo user04      # 添加到附加组
useradd -s /sbin/nologin user05   # 指定用户shell，默认使用/bin/bash
useradd -e "2025-12-31" user06    # 指定账户过期日期
useradd -M user07                 # 不创建家目录
useradd -r sysuser                # 创建系统用户（UID<1000）
id user01    # 查看用户的基本信息
```

使用`-d`选项创建家目录时，需要确保路径下不存在与家目录同名的目录，否则无法正常将`/etc/skel`目录下的初始环境变量文件复制到用户家目录下。需要注意的是，这个问题并不会影响用户的正常创建，但会影响到用户的登录，用户登录时会产生异常

useradd作为Linux系统用于添加新用户的主要工具，它使用系统的默认值和命令行参数来设置新账户属性信息，系统默认值被设置在`/etc/defaut/useradd`文件中，也可以通过`useradd -D`选项查看默认值；使用不同Linux发行版创建新用户时应先查看useradd的默认值，因为不同发行版的默认值不同，创建出来的新用户属性信息可能不符合管理员预期

```
GROUP=100               新用户会被添加到GID为100的公共组
HOME=/home              新用户的HOME将会位于/home/loginname
INACTIVE=-1             新用户账户密码过期后不会被禁用
EXPIRE=                 新用户账户不设置过期日期
SHELL=/bin/sh           新用户账户使用sh作为默认shell
SKEL=/etc/skel          将此目录下内容复制到新用户的HOME目录下
CREATE_MAIL_SPOOL=no    不为新用户创建用于接收邮件的文件
```

### 2.2 usermod — 修改用户

```bash
usermod -l newname oldname        # 改名
usermod -u 2000 user01            # 修改UID
usermod -d /new/home user01       # 修改家目录（需手动创建并复制文件）
usermod -m -d /new/home user01    # 移动家目录内容
usermod -s /bin/bash user01       # 修改Shell
usermod -aG group1 user01         # 追加附加组（-a必须与-G一起用）
usermod -L user01                 # 锁定账户（禁用密码登录）
usermod -U user01                 # 解锁账户
```

修改用户属性的前提是用户账户在系统上必须已存在。`usermod -d`选项实现的功能是反直觉的，它只是修改了`/etc/passwd`文件的用户信息而已，修改后的用户家目录以及隐藏文件都需要手动创建（或迁移）。

### 2.3 passwd — 设置密码

```bash
passwd                     # 修改当前用户密码
passwd user01              # 修改指定用户密码（root执行）
echo "password" | passwd --stdin user01   # 非交互式设置密码
passwd -l user01           # 锁定账户（比-L更安全）
passwd -u user01           # 解锁账户
passwd -d user01           # 清除密码（无密码登录）
passwd -e user01           # 强制下次登录改密码
passwd -n 7 user01         # 最短使用天数
passwd -x 90 user01        # 最长使用天数
passwd -w 7 user01         # 提前多少天警告
```

默认情况下创建的新账户是没有密码的，没有密码的账户不允许登录

### 2.4 chpasswd — 批量设置密码

```bash
# 格式：用户名:密码（每行一个）
echo "user01:pass01" > users.txt
echo "user02:pass02" >> users.txt
chpasswd < users.txt
```

### 2.5 su — 切换用户

```bash
su user01           # 切换用户（保留当前环境变量）
su - user01         # 完全切换（加载目标用户环境变量）
su - root           # 切换到root
su -c "command"    # 以其他用户身份执行命令
```

命令行切换账户时，使用`su`或`su -`都可以成功切换账户，两者的差异在于是否加载目标用户的profile环境变量，`su`命令直接使用只会对部分环境变量有影响，`su -`命令会完全切换到目标用户的环境变量。当用户shell为`/sbin/nologin`时，即便是root账户也无法使用su切换到该用户

### 2.6 userdel — 删除用户

```bash
userdel user01          # 删除用户，保留家目录
userdel -r user01       # 删除用户及其家目录、邮箱
userdel -f user01       # 强制删除（即使正在登录）
```

默认情况下用户处于登录状态时不可被删除。

在执行删除用户操作时需要注意，为了避免造成数据丢失，尽量不要删除用户，而是注释用户，或者将目标用户的SHELL改为`/sbin/nologin`。默认情况下userdel命令只会删除用户信息，即`/etc/passwd`等文件中所记录的用户信息，但不会删除用户的家目录，这可能会导致下次创建同名用户时，因用户家目录名称冲突导致创建用户异常。在创建新用户时使用`-g`参数，或先手动删除残留的用户家目录都可以解决这个问题

某些场景下在创建用户时就没有创建该用户的家目录，使用`userdel -r`删除此类用户时会提示找不到用户家目录的报错，但此时用户信息仍已经被成功删除了

## 三、用户组管理

```bash
groupadd group01           # 创建组
groupadd -g 1500 group02   # 指定GID
groupadd -r sysgroup       # 创建系统组

gpasswd group01           # 设置组密码
gpasswd -a user01 group01 # 添加用户到组
gpasswd -d user01 group01 # 从组移除用户
gpasswd -M user01,user02,user03 group01  # 批量设置组成员
gpasswd -A user01 group01 # 设置组管理员

groupmod -n newname oldname  # 修改组名
groupmod -g 2000 group01    # 修改GID

groupdel group01             # 删除组（基本组不可删除）
```

默认情况下在Linux系统中，只有root用户可以管理组成员，通过`gpasswd -A`将普通用户定义为某一个组的组管理员，使普通用户可以管理组成员，实现有限权限的下放。组管理员的权限依旧是比较有限的，组管理员可以通过添加、删除组成员来实现与`gpasswd -M`相同的效果，但组管理员仍没有权限直接使用gpasswd的`-M`、`-A`选项

## 四、Sudo 权限配置

### 4.1 语法配置格式

sudo命令的本质是权限的变更，它用于以其他人的身份执行命令，预设的身份为root。在`/etc/sudoers`中设置了可执行sudo指令的用户。若其未经授权的用户企图使用sudo，则会发出警告的邮件给管理员。用户使用sudo时，必须先输入密码，之后有5分钟的有效期限，超过期限则必须重新输入密码。sudo权限配置格式：

```bash
root    ALL=(ALL)       ALL

# 源用户  可执行命令的主机=(目标权限用户:目标用户组)  可执行命令
hebor  ALL=(root)  /usr/bin/more /etc/shadow,/usr/bin/more /etc/gshadow

# 上述语法在最大程度上限制了普通用户的权限只能操作某些文件，另一种方式是直接将某些命令的权限给到普通用户
hebor   ALL=(root)      /usr/bin/more,/usr/bin/echo

# 涉及到比较多的命令权限的问题时，可使用通配符，表示将目标目录下的所有可执行命令的权限给到普通用户
hebor   ALL=(root)      /usr/bin/*

# 由于通配符的权限过大，为了限制普通用户的权限，排除部分命令的权限不给于普通用户
hebor   ALL=(root)      /usr/bin/*,!/usr/bin/vim

# 免密码执行sudo，在可执行命令区域的最前面加上NOPASSWD:
hebor   ALL=(root)      NOPASSWD: /usr/bin/more,/usr/bin/echo

# 用户hebor在主机master上，可以以用户alex或jerry的身份执行kill命令
hebor   master=(alex,jerry)    /bin/kill

# 主机别名示例
Host_Alias  WEBSERVERS = web01,web02,web03
user01      WEBSERVERS=(ALL)  /usr/bin/systemctl restart httpd
```

一些比较特殊的系统服务用户，其“可执行命令的主机”和“可执行命令”一般都是ALL，当“可执行命令的主机”指定为具体的主机名时，源用户只能在该主机上具备有限的权限；当“目标权限用户”有多个时，可以通过`sudo -u`明确以某一个目标用户的身份执行命令，或直接在`/etc/sudoers`配置文件中申明默认以某个目标用户的权限执行命令

`/etc/sudoers`配置文件的编写需要注意“可执行命令”的语法编写格式，“可执行命令”必须使用命令的绝对路径，且不能使用井号注释符；需要授权多个权限命令的情况下，用逗号或空格进行分隔。当”目标权限用户“不是root时，对于Linux系统中默认存在的一些重要配置文件，即便sudo变更到其他普通用户仍然无法进行授权操作，如果一定要使普通用户能够修改文件，那么只能修改文件本身的权限。例如`/etc/hosts`文件本身就属于普通用户无权操作的类型，因此即便源用户hebor使用sudo变更权限为alex，仍无权对`/etc/hosts`文件进行操作

```bash
hebor   ALL=(alex)      /usr/bin/more /etc/shadow,/usr/bin/more /etc/gshadow,/usr/bin/echo 123 >> /etc/hosts
```

### 4.2 visudo

Linux系统建议使用visudo命令来配置用户的sudo权限，但实际上visudo命令本质上就是修改`/etc/sudoers`文件，通过vim直接编辑`/etc/sudoers`文件也可以实现与visudo命令同样的效果，建议使用visudo命令是因为此命令具备语法自动检查功能，配置编辑有误时visudo命令会有直观的提示。然而，手动编辑`/etc/sudoers`文件后也可以通过`visudo -c`手动检查`/etc/sudoers`文件的语法是否正确

```bash
visudo          # 编辑 /etc/sudoers（自带语法检查）
```

修改visudo的默认编辑器，修改默认编辑器之前需要先确保vim已经安装完成

```bash
vim /etc/sudoers
Defaults    editor=/usr/bin/vim    # 添加此行，vim的实际路径可以通过which命令检索
```

### 4.3 sudo日志

sudo日志默认不开启，需要修改`/etc/sudoers`配置文件手动开启日志，开启日志后可以通过`sudo -`切换到普通用户后执行一下`sudo`命令，再查看`sudo`日志文件是否存在记录

```bash
[root@master ~]# touch /var/log/sudo.log
[root@master ~]# visudo
...
Defaults    logfile=/var/log/sudo.log       # 添加此配置
...
```

> **su与sudo的区别**
>
> su命令直接切换到目标用户，sudo	命令只是临时执行目标用户权限的部分命令

### 4.4 sudo 相关命令

```bash
sudo -l              # 查看当前用户的sudo权限
sudo -u user01 cmd   # 以指定用户身份执行命令
sudo -k              # 清除缓存的密码（需重新输入）
sudo -i              # 切换到root（加载root环境）
```

## 五、文件权限管理

### 5.1 权限的概念

Linux 文件权限分为三组：所有者（Owner）、所属组（Group）、其他人（Other）

```
rwx rwx rwx
├── ├── └──
│   │    └── Other（其他人）权限
│    └── Group（所属组）权限
└── Owner（所有者）权限
```

权限含义：

| 权限 | 文件 | 目录 |
| :--- | :--- | :--- |
| `r` (4) | 可以读取文件内容 | 可以列出目录内容（文件名） |
| `w` (2) | 可以修改文件内容 | 可以在目录中创建/删除/重命名文件 |
| `x` (1) | 可以执行文件 | 可以进入目录（cd） |

### 5.2 chmod — 修改权限

```bash
# 符号方式
chmod u+x file              # 所有者增加执行权限
chmod g-rw file             # 所属组移除读写权限
chmod o=rw file             # 其他人设为读写
chmod a+x file             # 所有用户增加执行权限（a = ugo）
chmod u=rwx,g=rx,o=r file  # 精确设置

# 数字方式（最常用）
chmod 755 file              # rwxr-xr-x
chmod 644 file             # rw-r--r--
chmod 700 file             # rwx------
chmod 600 file             # rw-------
chmod 777 file             # rwxrwxrwx（慎用！）

# 递归修改
chmod -R 755 /data/project   # 递归修改目录及内容
chmod -R u+X /data          # 大写X：仅目录加执行权限，文件保持不变
```

### 5.3 chown — 修改所有者和所属组

```bash
chown user01 file                # 修改所有者
chown :group01 file              # 修改所属组
chown user01:group01 file        # 同时修改所有者和所属组
chown -R user01:group01 /data    # 递归修改
```

### 5.4 chgrp — 修改所属组（简化版）

```bash
chgrp group01 file              # 修改所属组
```

## 六、特殊权限

### 6.1 SUID（Set User ID）

- 作用于可执行文件
- 执行者临时获得文件所有者的权限
- 标识：`s`（在所有者x位上）

```bash
# 典型案例：/usr/bin/passwd
ls -l /usr/bin/passwd
# -rwsr-xr-x. 1 root root 27856 Apr  1  2020 /usr/bin/passwd
#                                    ^ s 表示有SUID

chmod u+s /usr/bin/command      # 添加SUID
chmod u-s /usr/bin/command      # 移除SUID
chmod 4755 /usr/bin/command     # 数字方式：4表示SUID
```

### 6.2 SGID（Set Group ID）

- 作用于可执行文件：执行者临时获得文件所属组的权限
- 作用于目录：目录下新建的文件自动继承目录的所属组
- 标识：`s`（在所属组x位上）

```bash
chmod g+s /project               # 添加SGID
chmod 2755 /project              # 数字方式：2表示SGID
```

### 6.3 Sticky Bit（粘滞位）

- 作用于目录
- 目录中的文件只能被所有者或root删除
- 标识：`t`（在其他用户x位上）
- 典型应用：`/tmp` 目录

```bash
ls -ld /tmp
# drwxrwxrwt. 163 root root 4096 /tmp
#                                     ^ t

chmod +t /shared                  # 添加粘滞位
chmod 1777 /shared                # 数字方式：1表示粘滞位
```

### 6.4 特殊权限速查

| 权限 | 数字 | 作用于 | 效果 | 标识位 |
| :--- | :--- | :--- | :--- | :--- |
| SUID | 4 | 文件 | 临时获取所有者权限 | s（所有者x位） |
| SGID | 2 | 文件/目录 | 文件：临时获取所属组权限；目录：文件继承目录组 | s（所属组x位） |
| Sticky Bit | 1 | 目录 | 文件只能被所有者和root删除 | t（其他x位） |

## 七、ACL 访问控制列表

### 7.1 基础命令

```bash
# 查看ACL权限
getfacl /data/file

# 设置ACL权限
setfacl -m u:user01:rw /data/file      # 单独设置用户权限
setfacl -m g:group01:rx /data/file     # 单独设置组权限
setfacl -m o::r /data/file             # 设置其他人权限
setfacl -m m::rwx /data/file           # 设置最大有效权限（mask）

# 递归设置
setfacl -R -m u:user01:rw /data        # 注意：-R要在-m前

# 删除ACL
setfacl -x u:user01 /data/file         # 删除指定用户的ACL
setfacl -x g:group01 /data/file        # 删除指定组的ACL
setfacl -b /data/file                  # 删除文件的所有ACL

# 默认ACL（仅对目录设置，子文件自动继承）
setfacl -m d:u:user01:rx /data         # 目录设置默认ACL
```

### 7.2 ACL 权限计算

```
Effective Permission = Min(ACL权限, Mask权限)
```

```bash
# 查看mask
getfacl /data/file
# mask::rwx        ← mask限制了实际生效权限

# 修改mask
setfacl -m m::r /data/file    # 即使u:user01有rwx，实际也只有r
```

### 7.3 ACL 与 chmod 的关系

- chmod 修改的是 **mask**，会间接影响所有 ACL 权限
- 修改所有者/所属组权限时，会自动更新 mask
- 建议：使用 `setfacl -m m::rwx` 确保 mask 不会限制 ACL 权限

## 八、权限验证示例

```bash
# 查看文件完整权限信息
ls -l /etc/passwd
# -rw-r--r--. 1 root root 2346 Apr  1  2020 /etc/passwd
# │││││││
# ││││││└── 1.扩展属性（.表示有SELinux上下文）
# │││││└──── 2.链接数
# ││││└───── 3.所有者
# │││└────── 4.所属组
# ││└─────── 5.文件大小
# │└──────── 6.最后修改时间
# └───────── 7.文件名

# 权限判断逻辑
1. 所有者匹配 → 用所有者权限
2. 否则，匹配所属组 → 用所属组权限  
3. 否则 → 用其他人权限
4. root用户可以无视权限做任何事
```

```bash
# 常见问题
# 1. 普通用户无法执行sudo → 检查/etc/sudoers配置
# 2. 用户无法写入目录 → 检查目录权限和父目录权限

id username              # 查看用户UID、GID、所属组
groups username          # 查看用户所属所有组
whoami                   # 显示当前用户名
```
